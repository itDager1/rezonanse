# Прозрачная вакансия

Мы — команда «Резонанс». Для онлайн-отбора КАНТКОД мы сделали сервис, который получает вакансии Калининградской области с портала «Работа в России» и проверяет, насколько понятно описаны условия. Результат — JSON-отчёт с вопросами, которые редактор может задать работодателю.

## Что делает сервис

- Загружает вакансии региона 39 по запросу или по расписанию. Адрес API, количество вакансий и размер страницы можно изменить в настройках.
- Принимает локальный JSON в формате ответа API. В проверочном режиме сервис обрабатывает все вакансии из файла и не обращается к порталу.
- Проверяет название должности, обязанности, требования, оплату, график, место работы и тип занятости. Для этого использует описание и структурированные поля вакансии.
- С помощью правил и ИИ находит пропуски, неясные формулировки и противоречия. В отчёт попадают исходные значения и рекомендации, что уточнить.
- Сохраняет один результат на ID вакансии. Если API недоступен, сообщает об ошибке и оставляет предыдущий успешный отчёт.

Обработка начинается с файла `main.py`. В `vacancy_analyzer/cli.py` находятся команды запуска и загрузка данных, в `vacancy_analyzer/analyzer.py` — правила анализа, в `vacancy_analyzer/ai.py` — работа с моделями ИИ.

## Зависимости и установка

Для работы нужен Python 3.10 или новее; дополнительные пакеты Python устанавливать не нужно. Для запуска через GigaChat понадобятся доступ к API и ключ авторизации. Для локального запуска нужны Ollama и интернет при первой загрузке модели.

Скачайте репозиторий и перейдите в его папку:

```bash
git clone https://github.com/itDager1/rezonanse.git
cd rezonanse
```

Чтобы посмотреть доступные команды и запустить тесты:

```bash
python main.py --help
python -m unittest discover -s tests -v
```

В Linux и macOS при необходимости используйте `python3` вместо `python`. По умолчанию отчёт сохраняется в `reports/report.json`.

## Запуск с GigaChat

Для этого варианта нужен собственный ключ GigaChat. В следующем разделе описан способ проверить проект с ИИ без покупки аккаунта.

1. Создайте файл `.env` из `.env.example`: выполните `Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Linux/macOS.
2. Откройте `.env` и укажите свой ключ в `GIGACHAT_CREDENTIALS`. Файл с ключом исключён из Git.
3. Запустите анализ учебного файла организаторов:

   ```bash
   python main.py check --input examples/kantkod_sample_vacancies.json --provider gigachat --output reports/check-gigachat.json
   ```

Сервис использует модель GigaChat-2 через API. В модель передаются поля вакансии, необходимые для анализа. Проверка TLS включена; если возникнет ошибка сертификата, воспользуйтесь инструкцией ниже.

### Если GigaChat сообщает об ошибке сертификата

На некоторых компьютерах для подключения нужен корневой сертификат Минцифры. В Windows откройте PowerShell в папке проекта и выполните:

```powershell
New-Item -ItemType Directory -Force -Path certs
Invoke-WebRequest -Uri "https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt" -OutFile "certs/russian_trusted_root_ca_pem.crt"
Test-Path -LiteralPath "certs/russian_trusted_root_ca_pem.crt"
```

Последняя команда должна вывести `True` — значит, файл находится по указанному пути. Затем добавьте путь в `.env`:

```text
GIGACHAT_CA_BUNDLE=certs/russian_trusted_root_ca_pem.crt
```

Сохраните `.env` и запустите команду ещё раз. Если сертификат лежит в другой папке, укажите его настоящий путь. Проверьте имя и расширение: `.crt` и `.crts` — разные имена. Папка может называться по-русски. Подходят сертификаты в формате PEM или DER. Подробнее — в [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates).

Если соединение не устанавливается, проверьте интернет, VPN и прокси. Для работы через Ollama сертификат GigaChat не требуется.

## Проверка для жюри без покупки аккаунта

Организаторы могут запустить проверку с локальной моделью через Ollama — аккаунт и ключ API для этого не нужны.

1. Установите Ollama: <https://ollama.com/download>.
2. Убедитесь, что Ollama запущена. Если приложение не запустило службу автоматически, выполните `ollama serve` в отдельном терминале и оставьте его открытым.
3. В другом терминале загрузите модель. Это нужно сделать только один раз:

   ```bash
   ollama pull qwen2.5:1.5b
   ```

4. В папке проекта выполните:

   ```bash
   python main.py check --input examples/kantkod_sample_vacancies.json --provider ollama --output reports/check.json
   ```

5. Откройте `reports/check.json`. Во время работы программа показывает ID вакансии и число замечаний от модели. Чтобы проверить другой набор, укажите его путь вместо `examples/kantkod_sample_vacancies.json`.

Модель `qwen2.5:1.5b` занимает около 1 ГБ на диске и использует оперативную память компьютера. Через `OLLAMA_MODEL`, `OLLAMA_BASE_URL` и `AI_TIMEOUT` можно изменить модель, адрес сервера и время ожидания. Если ИИ недоступен или ответ невозможно прочитать, программа сообщает об ошибке.

В `examples/kantkod_sample_vacancies.json` лежит учебный набор организаторов из 10 вакансий. Проверочная команда обрабатывает весь файл без обращения к порталу. Можно передать и другой JSON: объект с массивом `results.vacancies` или `vacancies` либо сам массив. Каждый элемент должен быть объектом вакансии или обёрткой `vacancy`.

## Рабочий запуск и расписание

Чтобы вручную получить до 10 вакансий региона 39, по 5 на странице, выполните:

```bash
python main.py run --provider gigachat --limit 10 --page-size 5 --output reports/report.json
```

Для локальной модели замените `gigachat` на `ollama`. Адрес источника можно изменить параметром `--url`. По умолчанию используется `https://opendata.trudvsem.ru/api/v1/vacancies/region/39`; [документация API](https://trudvsem.ru/opendata/api). Размер страницы — до 100 вакансий. Если хватает данных и позволяет лимит, сервис загружает несколько страниц.

Чтобы запускать обработку каждый день в 09:00:

```bash
python main.py schedule --provider gigachat --time 09:00
```

Расписание использует время компьютера и работает, пока запущен процесс. Для остановки нажмите Ctrl+C. Вместо этого можно настроить системный планировщик на команду `python main.py run` с рабочей папкой проекта. Пример для Linux находится в `schedule/crontab.example` — замените в нём путь на свой. Компьютер и планировщик должны быть включены во время запуска.

Основные настройки в `.env`: `SOURCE_URL`, `MAX_VACANCIES`, `PAGE_SIZE`, `SCHEDULE_TIME`, `REPORT_PATH` и `AI_PROVIDER`. Параметры команды имеют приоритет над настройками файла. Новый отчёт сохраняется после завершения анализа; при сбое API или ИИ предыдущий отчёт остаётся на месте.

## Формат отчёта

Отчёт — это массив JSON-объектов, по одному на каждую вакансию. Пример одного замечания из учебного набора:

```json
[
  {
    "id": "DEMO-39-002",
    "url": null,
    "findings": [
      {
        "topic": "график",
        "field": "schedule",
        "quote": "Гибкий график",
        "problem": "Указан гибкий график, но конкретные дни, смены или часы не уточнены.",
        "recommendation": "Уточните возможные рабочие дни, длительность смен и часы работы."
      }
    ]
  }
]
```

В каждой записи есть ID вакансии, ссылка `url` при её наличии и список замечаний `findings`. Если замечаний нет, список остаётся пустым. Для каждого замечания указаны тема (`topic`), поле источника (`field`), цитата или значение (`quote`), проблема (`problem`) и рекомендация (`recommendation`). Путь к полю указан без внешней обёртки `vacancy`. Если сведения отсутствуют, цитата остаётся пустой; при противоречии приводятся оба поля и значения.

Готовый отчёт на данных организаторов находится в `examples/kantkod_sample_report.json`. Он сформирован с GigaChat по файлу `examples/kantkod_sample_vacancies.json`.
