# Прозрачная вакансия

Прототип команды «Резонанс» для онлайн-отбора КАНТКОД. Сервис получает вакансии Калининградской области из открытого API «Работа в России», анализирует ясность условий и готовит JSON-отчёт для редактора. В нём указано, какие сведения стоит уточнить у работодателя.

## Возможности

- Рабочий режим получает вакансии региона 39 через API вручную или по расписанию. Адрес, предельное число вакансий и размер страницы настраиваются. В случае сбоя последний успешный отчёт не заменяется.
- Проверочный режим обрабатывает локальный JSON в формате API тем же анализатором, без запроса к порталу и без лимита на количество входных вакансий. В текущем отчёте сохраняется один объект на ID.
- Проверяются должность, обязанности, требования, оплата, график, место работы и тип занятости. Учитываются структурированные поля и свободный текст. Правила находят пропуски, некоторые неоднозначности и противоречие границ оплаты.
- В каждом режиме модель ИИ анализирует данные вакансии и предлагает дополнительные замечания об неоднозначностях. Приложение проверяет поле и дословную цитату по исходным данным и отклоняет непроверяемые цитаты. ИИ может ошибаться в смысловой интерпретации: итоговый отчёт предназначен для проверки редактором.

Начальная точка обработки — `main.py`; обработка режимов и загрузка API находятся в `vacancy_analyzer/cli.py`, правила — в `vacancy_analyzer/analyzer.py`, запросы к моделям — в `vacancy_analyzer/ai.py`.

## Зависимости и установка

Нужен Python 3.10 или новее. Сторонние пакеты Python не требуются. Для проверки с локальной моделью дополнительно нужны Ollama, интернет для первой загрузки модели и достаточно памяти и места на диске; после загрузки модели обращение к поставщику модели не требуется. Для GigaChat нужны доступ к API и учётные данные.

Склонируйте репозиторий и перейдите в его папку:

```bash
git clone <адрес-репозитория>
cd <папка-репозитория>
```

Проверка справки и тестов:

```bash
python main.py --help
python -m unittest discover -s tests -v
```

В Linux/macOS при необходимости используйте `python3` вместо `python`. Путь к отчёту по умолчанию: `reports/report.json`.

## Проверка для жюри без покупки аккаунта

Вариант с локальной моделью Ollama не требует аккаунта и ключа API:

1. Установите Ollama: <https://ollama.com/download>.
2. Запустите службу Ollama. В зависимости от установки она запускается приложением автоматически; если нет, выполните в отдельном терминале `ollama serve` и оставьте его открытым.
3. В другом терминале загрузите модель (только при первом использовании):

   ```bash
   ollama pull qwen2.5:1.5b
   ```

4. В папке проекта выполните:

   ```bash
   python main.py check --input examples/test_vacancies.json --provider ollama --output reports/check.json
   ```

5. Откройте `reports/check.json`. Сервис выводит номер вакансии и число принятых замечаний от модели. Чтобы проверить свой набор, подставьте путь к своему JSON вместо `examples/test_vacancies.json`.

Модель `qwen2.5:1.5b` занимает около 1 ГБ на диске, также нужен запас оперативной памяти. Скорость зависит от компьютера. Переменные `OLLAMA_MODEL`, `OLLAMA_BASE_URL` и `AI_TIMEOUT` позволяют выбрать другую совместимую модель, адрес и тайм-аут. Использование ИИ обязательно: если сервер или модель недоступны либо ответ нельзя разобрать, программа сообщает об ошибке и не выдаёт запуск одних правил за успешную проверку с ИИ.

`examples/test_vacancies.json` — искусственный пример команды, содержащий вымышленные вакансии и адреса. Учебный JSON организаторов на момент подготовки нам не передавался; после его получения можно передать его в `--input` и сформировать требуемый пример отчёта. Формат входа: объект с массивом `results.vacancies`, либо `vacancies`, либо сам массив; каждый элемент — вакансия или объект-обёртка `vacancy`.

## GigaChat

1. Скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в оболочке Unix).
2. Заполните `GIGACHAT_CREDENTIALS` своими учётными данными. Файл `.env` содержит секрет и исключён из Git.
3. Запустите проверку:

   ```bash
   python main.py check --input examples/test_vacancies.json --provider gigachat --output reports/check-gigachat.json
   ```

Используется модель GigaChat-2 через API GigaChat. TLS-проверка включена. Если система не доверяет сертификату сервиса, укажите путь к доверенному PEM-файлу в `GIGACHAT_CA_BUNDLE`; не выключайте проверку сертификатов. При отсутствии действующего ключа или сети программа сообщит об ошибке. Получение данных идёт только по нужным для анализа полям; итоговый вывод модели всё равно нужно проверять.

## Рабочий запуск и расписание

Ручное получение до 10 вакансий из API региона 39, страницами по 5:

```bash
python main.py run --provider gigachat --limit 10 --page-size 5 --output reports/report.json
```

Замените `gigachat` на `ollama`, если хотите использовать локальную модель. Параметр `--url` меняет URL источника. По умолчанию используется HTTPS-версия указанного в задании API: `https://opendata.trudvsem.ru/api/v1/vacancies/region/39`; документация: <https://trudvsem.ru/opendata/api>. Не более 100 записей на страницу. Если лимит и данные позволяют, загружается более одной страницы.

Ежедневный процесс на работающем компьютере:

```bash
python main.py schedule --provider gigachat --time 09:00
```

Он использует локальное время компьютера и работает, пока запущен процесс; остановка — Ctrl+C. Для запуска без постоянно открытого терминала можно настроить системный планировщик на команду `python main.py run` с рабочей папкой проекта. Для Linux пример строки cron находится в `schedule/crontab.example`; путь необходимо заменить на реальный. Компьютер и планировщик должны быть включены во время запуска.

Настройки в `.env` включают `SOURCE_URL`, `MAX_VACANCIES`, `PAGE_SIZE`, `SCHEDULE_TIME`, `REPORT_PATH`, `AI_PROVIDER`. Командные параметры переопределяют соответствующие значения. При сбое API или ИИ программа сообщает об ошибке и не заменяет предыдущий успешный отчёт; запись нового отчёта производится целиком после успешного анализа.

## Формат отчёта

Отчёт — массив JSON-объектов:

```json
[
  {
    "id": "example-001",
    "url": "https://example.org/vacancy/example-001",
    "findings": [
      {
        "topic": "график",
        "field": "schedule",
        "quote": "Гибкий график",
        "problem": "Не уточнены рабочие дни и часы.",
        "recommendation": "Уточните возможные дни и часы работы."
      }
    ]
  }
]
```

`id` — ID вакансии; `url` — ссылка при наличии, иначе `null`; `findings` — список замечаний или `[]`. В замечании `topic` — тема, `field` — путь к полю исходной вакансии без внешней обёртки `vacancy`, `quote` — исходная цитата или значение, `problem` — суть проблемы, `recommendation` — конкретное уточнение. Для пропуска `quote` пустая; при противоречии указаны оба поля и оба значения. Пример `examples/test_report.json` сформирован с Ollama на искусственных данных `examples/test_vacancies.json`; результат модели может незначительно меняться между запусками.

## Состав команды и вклад

Команда «Резонанс». Имена участников и распределение вклада будут дополнены командой после уточнения; неподтверждённые роли намеренно не указываются.

## Ограничения

Прототип проверяет понятность, а не достоверность вакансий или соблюдение законодательства. Некоторые детали могут быть выражены нестандартно, поэтому правила и модель могут пропустить проблему или предложить лишнее уточнение. Форму собственности работодателя сервис не определяет. Локальная модель не загружает вакансии с портала при проверке локального JSON; её установка и первая загрузка требуют интернета. При рабочем режиме и GigaChat доступны сетевые запросы к соответствующим сервисам.

Документация используемых сервисов: [API GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [сертификаты GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates), [Ollama API](https://docs.ollama.com/api/chat).
